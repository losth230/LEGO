## 1. Vision

L'application est **le double numérique de la vraie ville LEGO** posée sur la table. Chaque bâtiment construit en briques a son équivalent simulé ; chaque figurine est un habitant avec un nom, un métier et un compte en banque. La ville s'imagin(e) comme **une métropole d'environ un million d'habitants** — la table en est l'échantillon de figurines nommées. Le temps avance d'un clic : **un bouton fait passer les jours**. Chaque jour, la ville retient à la source l'impôt sur les gains de chacun et les habitants achètent dans les commerces ; le budget municipal finance ses services publics — police, pompiers — qui mobilisent leurs moyens face aux incidents.

**Principe directeur (arbitré 2026-11-05) : le réalisme est le point de départ, pas l'objectif — chaque arbitrage privilégie l'amusement.**

Trois promesses :

1. **Fidélité au réel (la table)** — la ville simulée reflète la ville physique : mêmes bâtiments, mêmes habitants.
2. **Cohérence économique réaliste comme base** — fiscalité, consommation, budgets et effectifs partent de **données françaises réelles** (data.gouv.fr, INSEE, ministère de l'Intérieur), jamais de valeurs inventées — puis le curseur du fun (coefficient d'intensité, référentiels éditables) dose le rythme.
3. **Une vie lisible** — des **tableaux et un journal** (très légèrement romancé) racontent ce qui s'y passe, jour après jour. Pas de carte : l'information vit dans des listes, des fiches et le journal.

## 2. Périmètre

**Dans le périmètre v1**

- Population de PNJ individuels (identité, métier, revenu indicatif, compte, foyer)
- Bâtiments avec fonction, valeur et occupants
- **Économie en circuit court** : impôt prélevé à la source sur les gains du jour (soldes, salaires privés, marges) → budget municipal → salaires des agents publics ; **achats quotidiens des habitants dans les commerces → revenus des commerçants**
- Budget municipal (équilibre, déficit, dette)
- Services de sécurité : police, pompiers (effectifs, moyens, interventions)
- Avancement du temps manuel : **bouton « Passer un jour »** — l'unité de règlement est **la journée**
- Journal des événements + tableaux d'indicateurs
- **Objectifs optionnels activables** : équilibre budgétaire, sécurité, incendie, secours — des indicateurs qui alertent sans bloquer ; la simulation reste un **bac à sable**
- Éditeur du monde (ajouter/modifier bâtiments et habitants pour coller à la vraie ville)

**Hors périmètre v1** (arbitré ou candidat pour des phases ultérieures)

- **Taxe foncière** — arbitré : pas pour l'instant (2026-11-05)
- **Salaires privés** — v1 : arbitré « pas de flux salarial des employeurs privés » (2026-11-05) ; **remplacé en phase 3.6 (2026-11-05)** par le **modèle flux** : un commerce redistribue ses recettes du jour (salaires de ses employés + primes partagées), seule la marge patronale (12 %) reste au patron ; un commerce sans employé thésaurise et le journal le raconte — c'est au joueur d'embaucher pour remettre l'argent en circulation
- **Carte de la ville** — arbitré : des tableaux et journaux suffisent (2026-11-05)
- **Horloge temps réel / vitesses ×N** — arbitré : uniquement le bouton « Passer un jour » (2026-11-05)
- **Cycle de vie des habitants** — arbitré : pas de vieillissement ni de mort de vieillesse ; naissances, décès, départs/arrivées n'existent **que comme événements** tirés par le moteur d'événements (2026-11-05)
- Multijoueur / sauvegarde en ligne
- Rendu 3D, simulation de trafic
- Module « tour des héros » et menaces de super-vilains (narratif — phase ultérieure)

## 3. Le monde — modèle de données

| Attribut | Description |
|---|---|
| Identité | Nom, type, quartier |
| Type | Habitation, Commerce (avec un PNJ commerçant à sa tête), Service public (mairie, police, pompiers, école), Tour des héros, Industrie |
| Vocations | Pour un commerce (v1.31) : une **liste de services cochés** — santé, BTP, banque, station-service (monde fermé, 2026-11-06) — cumulables dans le même bâtiment (la station-service qui est aussi la supérette du village), plus une case **« boutique »** indépendante pour vendre aux habitants (courses, fonctionnement municipal). La détention se joue au commissariat, pas dans un commerce à vocation (correction 2026-11-06). Chaque service n'est ouvert que si le commerce a son gérant ; sans lui, la mécanique liée dort |
| Capacité | Logements et/ou postes de travail (v1.24 : la capacité unique est dédoublée — un commerce peut loger ses employés au-dessus de la boutique) |
| Valeurs | Valeur (dépréciée par les sinistres), coût de fonctionnement quotidien pour les services publics |
| État | Neuf / bon / dégradé / sinistré (les incidents dégradent l'état) |

### 3.2 PNJ (habitants)

| Attribut | Description |
|---|---|
| Identité | Prénom, nom, âge, genre — l'âge est **fixe** (pas de vieillissement) |
| Foyer | Famille (couple, enfants), logement occupé |
| Métier | Étiquette narrative + **revenu indicatif** (assiette fiscale uniquement) |
| Statut | **Agent public** (salaire quotidien versé par la ville) / **Commerçant** (encaisse les achats des habitants) / privé hors commerce (aucun flux régulier — voir §4.3) ; **v1.33 : le commerçant peut être patron de PLUSIEURS commerces** (liste `commercesId`, le bâtiment lié redevient un lien narratif de logement) |
| Comptes | Compte courant + épargne |
| Carte d'identité (phase 3.9) | **Personnalité** (2 traits, liste fermée), **casier judiciaire**, **gang** — le profil criminel pondère les tirages de cambriolage ; affichée en fiche PNJ, éditable |

> **Rappel d'arbitrage :** naissance, décès, emménagement ne surviennent **que par événement** (§4.2), jamais par écoulement du temps.

### 3.3 La ville (niveau collectif)

- **Budget municipal** : recettes = impôt à la source sur les gains du jour (seule forme d'impôt) ; dépenses = salaires quotidiens des agents publics + coûts de fonctionnement des services + carburant de la flotte + investissement + dette
- **Services** : police (effectifs, véhicules), pompiers (casernes, moyens, temps d'intervention), éducation, santé
- **Indicateurs** : sécurité, richesse moyenne, solde budgétaire — dans le temps

### 3.4 Véhicules (v1.25)

| Attribut | Description |
|---|---|
| Identité | Nom, quartier |
| Catégorie | **Municipal** (rôle : pompiers, police, propreté, santé, chantier) ou **privé** (propriétaire figurine — volable par le milieu) ; un **engin de chantier** (rôle « chantier », municipal ou privé) porte une **efficacité** (v1.28) : ses travaux/jour sur le chantier en cours, entier ≥ 1, défaut 2 sans fiche |
| Capacités | Mêmes capacités que les bâtiments : **logements** (caravane, lien `batimentId`) et **postes de travail** (fourgon affecté, lien `travailBatimentId`) |
| Carburant | Consommation quotidienne (`essenceJour`, défaut 8 L/j) achetée **à la station-service** (commerce à vocation « garage », arbitrage Thibaut 2026-11-08 : c'est elle qui gère la pompe et les accidents, pas le BTP) — tout ou rien, la pompe ne fait pas crédit ; sans station-service ou sans caisse, le véhicule reste au garage et son rôle dort ce jour-là ; **engins de chantier (v1.29)** : plus de pompe quotidienne — chaque engin porte un **réservoir** (`carburant`, 0 à 50 L, plein au départ) et brûle **1 L par travail posé** ; à sec, il ne produit pas : son propriétaire lui fait **le plein de 50 L** à la station (la figurine elle-même si elle travaille pour elle-même, sinon son patron — arbitrage Thibaut 2026-11-08 ; la ville paie pour un engin municipal ; tout ou rien, sans station ou sans caisse l'engin reste à sec) |
| Valeurs | Valeur (dépréciée par les collisions non réparées), état (neuf / bon / dégradé / sinistré) |
| Garage | Bâtiment d'affectation : les postes du véhicule s'ajoutent à ceux du bâtiment qui l'accueille |

> **Rôles municipaux en service** (l'engin doit avoir roulé) : camion de pompiers → dégâts d'incendie ÷ 2 ; fourgon de police → arrestation sur le fait exigée (cambriolage comme vol de voiture, sinon moitié du butin et casier) ; camion de propreté → dégâts de collision non doublés ; ambulance → frais médicaux non doublés.

## 4. La simulation

### 4.1 Avancement du temps

- **Un seul contrôle : le bouton « Passer un jour ».** Pas d'horloge, pas de vitesse.
- Chaque journée déclenche un **règlement quotidien** dans cet ordre : salaires publics versés (**impôt retenu à la source sur chaque solde**, arbitrage 2026-11-06) → **primes de garde** versées aux policiers en poste pour chaque détenu du jour (5 L/jour/détenu, phase 3.10 — les détenus sont gardés au commissariat ; même sans boutique ouverte, on ne rationne pas les prisons par fantaisie commerciale ; sans police, rien n'est payé) → coûts de fonctionnement payés **sur place** aux commerces ouverts (rien n'est dépensé s'il n'y en a pas — monde fermé) → **carburant de la flotte acheté à la station-service** (vocation « garage », v1.25 — sans station, la flotte dort) → intérêts de dette versés à la **banque locale** (sans banque, la dette dort) → achats des habitants dans les commerces (budget modulé par la personnalité, phase 3.10) → **chantiers de la ville (v1.27)** : le premier chantier de la file avance — les employés du constructeur produisent 1 travail chacun, les engins de chantier qui ont roulé produisent selon leur efficacité (v1.28, défaut 2) dans la limite de leur réservoir (v1.29 : 1 L par travail posé ; un engin à sec passe la journée à faire le plein et ne produit pas), le payeur règle l'acompte au prorata (tout ou rien : faute de budget, pause ; sans constructeur en ville, l'ouvrage avance à la main, 1 travail/jour sans paiement) ; un chantier livré réveille sa cible (capacités actives) → **incidents de la journée tirés et NOTIFIÉS (v1.26)** : chaque incident rejoint la file des arbitrages du maître du jeu — le joueur choisit l'issue dans l'onglet Arbitrages (l'issue attendue est suggérée), le jeu applique les L ; sans réponse sous 3 jours, **la pire issue s'impose seule** au règlement suivant (les faits — engins en service, renforts, hôpital, station — se rejouent sur les moyens photographiés le jour de l'incident) → **libérations et rédemptions** (phase 3.10 : à sa sortie, un détenu peut perdre un trait criminel — 50 % si la police est au moins aussi nombreuse que les détenus du jour, 10 % si le commissariat est débordé) → **redistribution du flux le soir** (salaires privés + primes, phase 3.6, impôt retenu à la source sur chaque part et sur la marge ; les résolutions tombées pendant le règlement rejoignent les recettes du soir) → puis le journal raconte la journée.

### 4.2 Moteurs (exécutés à chaque passage de jour)

1. **Moteur économique (circuit court)** — versement quotidien des salaires aux agents publics avec **impôt retenu à la source sur chaque gain versé** (arbitrage 2026-11-06 : X % des gains réels du jour, une seule forme d'impôt) → budget municipal ; paiement des coûts de fonctionnement **auprès des commerces locaux** (rien n'est dépensé si aucune boutique n'est ouverte — monde fermé) ; **achats quotidiens des habitants** (budget consommation calibré sur les dépenses réelles des ménages) répartis entre les commerces de la ville → les commerçants encaissent ; **redistribution du flux (phase 3.6)** : chaque commerce reverse ses recettes du jour — salaires de ses employés privés (contractuels, payés d'abord), puis primes partagées jusqu'à 88 % des recettes ; seule la marge patronale (12 %) reste au patron, l'argent ne s'accumule jamais en stock d'entreprise ; l'impôt à la source s'applique aussi aux salaires, primes et marges privés — un habitant sans gain ne paie rien.
2. **Moteur d'événements** — tirage probabiliste des **incidents** (incendies, cambriolages, accidents de la route, pannes) selon la **règle d'échelle §5** (taux réels × coefficient d'intensité 1 000), ET des **faits de vie** (une naissance, un accident de la vie, un ménage qui arrive ou repart) — seule porte d'entrée des changements de population.
3. **Moteur de services & arbitrages (v1.26)** — chaque incident mobilise les moyens disponibles : effectifs de garde, gravité → réussite/délai/échec de l'intervention, conséquences matérielles et humaines (amendes, dommages). **Le maître du jeu tranche (v1.26, arbitrage Thibaut 2026-11-08)** : la simulation ne décide plus de l'issue — elle calcule les issues possibles selon les moyens photographiés au moment de l'incident (incendie : maîtrisé / débordé / ravageur ; cambriolage : déjoué / fuite / butin ; guerre de gangs : vainqueur au choix ; collision : réparé à la station-service / sinistré ; vol de voiture : déjoué / transfert de propriété ; accident : soins contenus / aggravés) et offre le choix au joueur ; le jeu applique les L de l'issue choisie ; **sans réponse sous 3 jours, la pire issue s'impose automatiquement** (la partie n'est jamais bloquée). Les **faits** se jouent seuls sur l'issue choisie : camion de pompiers ÷ 2, renfort de la garnison, camion de propreté, ambulance. **Monde 100 % fermé (2026-11-06)** : les conséquences pécuniaires passent par les **services locaux à vocation** — soins facturés à l'hôpital, réparations des bâtiments payées au BTP, essence et réparations des véhicules à la **station-service** (vocation « garage », arbitrage Thibaut 2026-11-08 : c'est elle qui gère les accidents, pas le BTP), intérêts à la banque — et **dorment si le service n'existe pas ou n'a pas de gérant** : sans hôpital, aucun frais de santé ; sans BTP, le bâtiment sinistré reste marqué ; sans station-service, la flotte dort au garage et les véhicules accidentés restent sinistrés ; sans banque, ni crédit ni intérêts.

4. **Moteur de chantiers (v1.27, `src/engine/chantiers.ts`)** — plus de création instantanée (arbitrage Thibaut 2026-11-08) : les bâtiments se construisent au **BTP**, les véhicules s'assemblent à la **station-service**. La durée d'un chantier est une **valeur de travaux** (défaut 100) : un ouvrier produit 1 travail/jour, un engin de chantier qui a roulé produit selon son **efficacité** (v1.28 : fiche du véhicule, entier ≥ 1, défaut 2 — `efficaciteEngin`) **dans la limite de son réservoir** (v1.29 : 50 L, **1 L brûlé par travail réellement posé** — un chantier livré en cours de journée ne consomme que ce qui a été posé ; à sec → la journée commence par **le plein de 50 L** à la station-service, payé par le propriétaire (figurine ou patron) ou la ville, sans station ou sans caisse l'engin reste à sec et ne produit pas). Le coût (défaut 50 % de la valeur) se règle **au prorata de l'avancement** — la ville paie pour un acteur public, la figurine commanditaire pour un privé (tout ou rien : caisse insuffisante → pause, le chantier reprendra). Un seul chantier avance par jour (FIFO, priorisable par le maître du jeu). **Amorçage** : sans constructeur en ville, l'ouvrage avance à la main (1 travail/jour, sans paiement) — la ville nue peut bâtir son premier BTP. La cible est visible « en construction » (badge et %), ses capacités sont **inactives** jusqu'à la livraison (« 🏗 Dernière brique ») ; cible disparue → classé sans suite sans crash.

### 4.3 Circuit court de la monnaie (comptabilité fermée)

L'argent ne naît ni ne disparaît : il **circule en boucle courte**.

- Comptes : **PNJ** (courant + épargne) et **ville** (budget).
- Flux PNJ ↔ ville : impôt à la source **gain du jour → ville** ; salaire quotidien **ville → agent public** ; fonctionnement **ville → commerces locaux** (phase 3.6 : acheté sur place, l'argent reste dans le circuit ; sans boutique ouverte, la ville ne s'équipe pas et ne dépense rien) ; amende **PNJ → ville** (via événement).
- Flux PNJ ↔ PNJ : achat quotidien **habitant → commerçant** ; puis chaque soir, **commerce → employés privés** : salaires contractuels + primes partagées jusqu'à 88 % des recettes, marge patronale (12 %) au patron (phase 3.6 — modèle flux).
- **Sorties documentées du circuit : aucune (monde 100 % fermé, 2026-11-06).** Tout reste en ville : les intérêts de la dette vont à la banque locale, les réparations des bâtiments au BTP de la ville, **l'essence et les réparations des véhicules à la station-service (vocation « garage », v1.25)**, les frais de soins à l'hôpital, le fonctionnement aux commerces ouverts, **les primes de garde aux policiers du commissariat** (phase 3.10, impôt à la source retenu comme sur toute solde) — **et le butin des cambriolages à la poche du voleur, un figurant de la ville (le crime ne détruit plus la monnaie)**, ainsi que les pillages des guerres de gangs (phase 3.9 : transferts internes tracés dans `volsCumules`). La seule création monétaire : les **emprunts** contractés auprès de la banque locale (création monétaire tracée), remboursables au banquier — l'argent du remboursement reste en ville. La seule perte réelle restante est **patrimoniale, pas monétaire** : la valeur des bâtiments sinistrés que le BTP n'a pas réparés (usure).
- **Modèle flux, jamais le stock (arbitrage phase 3.6)** : un commerce est une pompe, pas un réservoir — ses recettes du jour repartent le soir même ; un commerce sans employé garde tout et le journal le raconte (« l'argent s'accumule (stock) »), c'est au joueur d'embaucher. Calibrage : `effectif_max ≈ 0,88 × recettes / 57,75`.
- **Cas limite assumé** : un PNJ privé **sans emploi** ne reçoit aucun flux régulier — son compte s'érode par les achats (et il ne paie pas d'impôt, faute de gains). Les PNJ concernés peuvent être embauchés dans l'éditeur (lieu de travail) ou définis commerçants/agents publics ; c'est un choix de peuplement, pas un bug du moteur.

### 4.4 Exemple de chaîne causale

Incendie déclaré (probabilité calée sur les statistiques réelles × coefficient d'intensité) → les pompiers engagent des moyens selon la gravité → si l'effectif de garde est insuffisant, le délai augmente et les dégâts sont plus lourds → réparations payées par la ville à l'entreprise de BTP locale (sans BTP, le bâtiment reste marqué) → creux dans le budget municipal → arbitrage : la ville diffère un investissement ou **augmente le taux d'imposition quotidien**.

**Chaque maillon de la chaîne est visible dans le journal de la ville.**

### Règle d'échelle (actée — 2026-11-05, K abaissé le même jour)

La ville LEGO est **une échelle très réduite** (les figurines nommées, quelques dizaines), mais s'imagin(e) comme **une métropole ≈ 1 million d'habitants** — identité narrative ; le rythme des événements, lui, est dosé par un **curseur d'amusement** :

- **Événements — coefficient d'intensité K = 1 000** (éditable dans les référentiels). Pour un incident de taux réel `R` (événements par an pour 10 000 habitants) et une population de `P` figurines :
  `proba quotidienne = R × P × K / 10 000 / 365`, avec `K = 1 000`.
  Exemple avec le taux réel d'incendies (≈ 34,2 pour 10 000 hab./an, DGSCGC 2024) et P = 60 figurines : **≈ 0,56 incendie/jour** — un incendie tous les deux jours environ : assez pour animer le journal, assez rare pour que les pompiers de la ville restent à la hauteur. Le curseur : K = 100 = très calme, K = 1 000 = animé (défaut), K = 10 000 = métropole frénétique.
- **Économie — valeurs réelles par habitant de la ville de référence, appliquées telles quelles aux figurines** (impôt quotidien ≈ budget communal par habitant / 365, salaires publics réels, consommation quotidienne réelle par ménage). Les comptes restent à l'échelle figurine pour préserver le circuit court : le « million d'habitants » est la population **imaginée**, pas une masse monétaire multipliée.

### Ville de référence (actée — 2026-11-05)

**Une seule ville : Marseille (~875 000 habitants)** — la commune française la plus proche du million, couverte par toutes les sources communales qualifiées. Ses valeurs par habitant servent d'ancrage économique ; le réalisme est le point de départ, l'amusement arbitre (coefficient d'intensité, référentiels éditables).

N) » dans le tableau Véhicules, un engin de chantier peut être privé (il travaille pour sa figurine) ; **réservoir (v1.29)** : jauge « ⛽ N/50 » dans le tableau Véhicules (« — à sec » si vide), champ Carburant dans l'éditeur et le lancement de chantier, ligne « équipe du jour » qui signale les engins à sec (journée de plein, pas de production) ; **panneau 🚚 Nouvel arrivant (v1.30)** : un formulaire unique accueille la figurine avec, au choix, sa maison (habitation reliée comme logement) et/ou son véhicule (à son nom — voiture à la pompe quotidienne ou engin de chantier au réservoir plein), une entrée de journal raconte l'installation ; **vocations multiples (v1.31)** : le panneau 🧱 Bâtiments propose des cases à cocher — chaque vocation cumulée rend son service, la case « boutique de consommation » ajoute les courses, badge 🛒 dans le tableau Bâtiments ; **panneau ☁️ En ligne (v1.32)** : depuis la barre d'outils, les 3 emplacements Ville A/B/C (contenu affiché : jour, figurines, caisse), ⬆ Envoyer / ⬇ Charger avec confirmation avant d'écraser la ville en cours, jeton GitHub mémorisé/effacé sur place ; **suggestions de métiers (v1.32)** : les champs métier (Nouvel arrivant, éditeur PNJ, création) restent libres mais proposent les métiers de la ville de démonstration en datalist

- **Journal de la ville** — les événements racontés, **très légèrement romancés** (« 12 mars : le four du boulanger a pris feu au petit matin ; 4 pompiers ont eu raison des flammes, 2 400 L de dégâts »)
- **Objectifs optionnels** — panneau activable : équilibre budgétaire, sécurité (criminalité, délai d'intervention police), incendie/secours (délai moyen et taux de réussite des interventions) ; alertes sans écran de défaite
- **Éditeur du monde** — créer/modifier/renommer bâtiments et habitants ; **panneau Gangs (phase 3.10)** : installer un gang (nom + territoire initial parmi les quartiers bâtis) ou le démanteler (les membres redeviennent indépendants), le journal raconte chaque coup
- **Mode clair / sombre** — bouton ☀️/🌙 dans la barre de la ville ; le choix est gardé entre les sessions (localStorage), le sombre est le défaut ; appliqué avant le premier rendu (pas de flash)
- **Référentiels** — tous les paramètres (taux d'imposition, consommation quotidienne, salaires publics, effectifs, probabilités, coefficient d'intensité) consultables et modifiables, avec leur source

## 7. Architecture technique (proposée)

- **React + TypeScript, déployé sur GitHub Pages** — même socle que le jeu Chasse & Pêche (push = CI + Pages, éprouvé)
- **Moteur de simulation pur** : fonctions déterministes, testables, sans dépendance React ; état versionné avec registre de migrations (retour d'expérience CP)
- **Référentiel de données réelles en JSON** versionné dans le repo (licence ouverte — mention de source dans l'application)
- **Persistance** : localStorage + export/import JSON ; **v1.32 : sauvegardes en ligne** — 3 emplacements (`sauvegardes/ville-{a,b,c}.json`) dans le dépôt GitHub du jeu via l'API Contents et un jeton fine-grained (Contents : Read and write sur `losth230/LEGO` uniquement) mémorisé dans le navigateur ; boutons manuels ⬆ Envoyer / ⬇ Charger, chaque envoi est un commit (l'historique GitHub garde toutes les sauvegardes) ; lecture possible sans jeton (dépôt public), envoi impossible sans lui ; le chargement passe par `migrerEtat` comme toute ingestion
- **Tests** : moteur couvert par un harnais de tests unitaires (node), rendu vérifié avant push

## 10. État de l'art et positionnement (veille 2026-11-05)

**Le projet n'existe pas déjà sous cette forme.** Aucun outil trouvé ne combine un jumeau numérique de sa propre ville LEGO, des PNJ nommés avec comptes en banque en circuit fermé, et une calibration sur données publiques françaises réelles. Les plus proches :

- **[MIT CityScope](https://www.media.mit.edu/projects/cityscope/)** — briques tangibles + simulation urbaine, mais pour ateliers de planification : pas de PNJ ni de ville personnelle ;
- **[emergent-city](https://github.com/leatag/emergent-city), [manyworld](https://github.com/alinojoumi8/manyworld), [AgentSociety](https://deepwiki.com/tsinghua-fib-lab/AgentSociety/12.2-mobility-and-economic-simulations)** — simulations de société à agents individuels open source, mais villes fictives, sans données réelles ni LEGO ;
- **Jeux commerciaux** — The Sims, Dwarf Fortress (individus profonds), Cities: Skylines/SimCity (économies agrégées) : aucun ne suit l'argent de chaque citoyen nommé d'une ville réelle du joueur ;
- **LEGO officiel** — LEGO Tower, LEGO City Build and Protect : gestion fiction, sans jumeau numérique.
